# Desktop launcher

One-click launcher for **The Digital Side — Command Center** so it opens from the Chromebook
(Crostini) / Linux app launcher with no terminal.

## Files

| File | Purpose |
|---|---|
| `launch.sh` | What the launcher runs. Runs the already-built Tauri binary at `src-tauri/target/debug/tds-command-center` **directly** — never `tauri dev`, never cargo, so it can't get stuck compiling. If that binary is a dev build (loads `http://localhost:1420`), the script first ensures the Vite dev server is up on 1420 (starts it detached, `flock`-guarded, waits for it), then launches the app. If it's a standalone build, it just runs it. Reuses an already-running Vite server. Writes `launch.log` here. |
| `install-launcher.sh` | Writes `~/.local/share/applications/the-digital-side-command-center.desktop` with absolute paths for this checkout. Idempotent. |
| `the-digital-side-command-center.desktop` | Reference copy (the installed one is generated by `install-launcher.sh`). |

## Install

```
bash command-center/desktop/install-launcher.sh
```

Then, in the Chromebook launcher, search **"Command Center"** (or **"The Digital Side"**),
click to open, right-click → pin to shelf if you want it permanent.

First launch takes ~3–5 s (Vite starts, then the window opens). Later launches are quicker if
Vite is still up.

## Notes

- Uses only the existing Tauri build system + Vite. No new services, nothing paid.
- Does not disturb `npm run tauri dev` — if a dev server is already on port 1420 the launcher
  attaches to it instead of starting another, and it never rebuilds anything.
- `.desktop` uses `StartupNotify=false` on purpose: a wrapper script breaks the ChromeOS
  startup-notification handshake, and with it on the shelf shows an endless loading spinner.
- Icon is the existing project master icon (`src-tauri/icons/icon.png`).
- The launcher runs whatever `tds-command-center` binary exists. `npm run tauri dev` keeps that
  a *dev* binary (needs Vite). A one-time `npm run tauri build -- --debug --no-bundle` makes it
  *standalone* (frontend embedded, no Vite needed); `launch.sh` detects and handles either.
- Troubleshooting: `cat command-center/desktop/launch.log` (and `vite.log`) after a click.
